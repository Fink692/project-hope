# Project Hope 1.0.0 — Built for the people doing the work

Project Hope 1.0 is the first complete release-hardened baseline of a self-hosted operations platform for charities.

It is deliberately practical: one calm workspace for the work that keeps a community organization moving, with strong boundaries around data, automation, and human judgment.

## What ships

- Organization-scoped identity, RBAC, tenant isolation, audit history, retention policies, legal holds, and exports.
- CRM, volunteers, scheduling, documents, search, grants, resources, translation, analytics, and donor insights.
- A bounded local AI gateway with deterministic fallback, review states, risk flags, and no unrestricted autonomous actions.
- Safe email workflows with minimized mailbox imports, injection detection, approval gates, and SMTP delivery.
- Accessible React web PWA with protected offline behavior and a secure Expo mobile client for field work.
- Governed plugins, scoped public API clients, capability tokens, Caddy reverse-proxy routing, worker processing, backups, and production Compose deployment.

## Quality signals

- 24 backend tests passing on SQLite and PostgreSQL/pgvector.
- Ruff, Mypy, migration-drift, Django deployment, web, API-client, and mobile checks passing.
- Expo Doctor: 20/20 checks passing.
- Development stack: healthy database, cache, gateway, web, core, worker, mail, identity, and proxy services.
- Production profile: healthy Gunicorn topology, HTTPS route, collected static assets, secure HTTP redirect, worker ordering, and clean `check --deploy`.

## The philosophy

Project Hope is built for organizations that need useful technology without surrendering control of their data or their judgment. AI is optional. Review is explicit. Privacy is part of the product surface. Infrastructure is replaceable. Accessibility is not a stretch goal.

## Before real production data

Operators must still configure their own domain, TLS/DNS, high-entropy secrets, SMTP, MFA-backed identity provider, backup restore process, staging smoke test, and Apple/Android signing credentials. Those are organization-owned launch controls, not hidden software dependencies.
